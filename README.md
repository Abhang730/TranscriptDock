# TranscriptDock

Turn video captions into clean, searchable transcripts.

TranscriptDock is a full-stack SaaS application: a Next.js (App Router) frontend,
a FastAPI backend, Supabase Auth/Postgres, Razorpay one-time payments, and a
**clearly labelled demo transcript provider**. Real transcription is deliberately
unavailable until an authorized provider is configured.

> **Demo status:** every transcript produced by this build is generated by
> `api/app/services/demo_provider.py`. It never contacts YouTube and is labelled
> "Demo data" in the UI, API and exported files. Do not describe it as real
> transcription.

## 2. Architecture

```text
transcript_generator/
├── web/                      Next.js 15 (App Router), React 19, TypeScript, Tailwind 3
│   ├── app/                  routes (marketing group + app + /api BFF)
│   ├── components/           ui/ primitives, web/ marketing, tool/ workflows, auth/, account/
│   ├── lib/                  supabase clients, backend client, types, URL validation
│   └── middleware.ts         session refresh + protection for /dashboard, /settings
├── api/                      FastAPI backend
│   ├── app/
│   │   ├── main.py           app factory, CORS, security headers, error handling
│   │   ├── auth/             Supabase JWT verification (HS256 or JWKS)
│   │   ├── database/         store interface, memory + Supabase stores, schema.sql
│   │   ├── routes/           health, config, jobs, playlists, credits, payments, webhooks, account
│   │   └── services/         provider abstraction, demo provider, jobs, credits, exports, payments
│   └── tests/                pytest suite (backend, no network)
├── .env.example              all environment variables
└── README.md
```

Request path: browser → same-origin `/api/*` BFF route → FastAPI `/v1/*` with the
user's Supabase access token attached server-side. The browser never learns the
API origin and never sends an amount, credit balance or user id.

### Data flow

1. A job is created (`single` or `playlist`). URLs are parsed against a strict
   YouTube allowlist; only video/playlist **ids** reach the provider (no
   arbitrary server-side fetching, so no SSRF).
2. Single jobs process inline (demo is instant). Playlist jobs are persisted as
   `pending`, processed in the background with bounded concurrency, and polled
   by the browser. No request stays open for a batch.
3. Credits are charged **only** for successful transcripts, once per item id.
   Anonymous users may run one limited single-video demo; playlists require an
   account.
4. Exports (TXT/SRT/VTT/CSV/ZIP) are generated server-side from stored records.

## 3. Local setup

Prerequisites: Node.js 20+ (verified on 24), Python 3.12+.

### 3.1 Frontend

```bash
cd web
npm install
cp .env.example .env.local      # optional: fill in Supabase values
npm run dev                     # http://localhost:3000
```

### 3.2 Backend

Windows (verified):

```bash
cd api
python -m venv .venv
./.venv/Scripts/python -m pip install -r requirements-dev.txt
./.venv/Scripts/python -m uvicorn app.main:app --reload --port 8000
```

macOS/Linux:

```bash
cd api
python -m venv .venv
./.venv/bin/python -m pip install -r requirements-dev.txt
./.venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

Health: <http://127.0.0.1:8000/v1/health> · API docs (non-production):
<http://127.0.0.1:8000/docs>.

Keep `API_ORIGIN=http://127.0.0.1:8000` in `web/.env.local` so the BFF can reach
the API. The single-video demo flow works with no Supabase and no Razorpay keys.

### 3.3 Environment

All variables are documented in `.env.example`. Backend reads `api/.env` or the
repository root `.env`; frontend reads `web/.env.local`. Never commit secrets.

**Persistence safety guard.** `STORE_BACKEND=memory` is a demo store: accounts,
jobs, transcripts and credits disappear on restart. It is accepted only when
`APP_ENV` is not `production`. With `APP_ENV=production` the API logs
`Refusing to start …` and aborts rather than silently running on ephemeral
storage; set `STORE_BACKEND=supabase` plus `SUPABASE_URL` and
`SUPABASE_SERVICE_ROLE_KEY` before deploying. Unknown `STORE_BACKEND` values
also fail at startup instead of falling back to memory. This guard does not
affect local demo runs, which keep using memory by default.

## 4. Supabase setup (required for accounts, history, playlists)

1. Create a project at <https://supabase.com> (free tier is sufficient to start).
2. Open **SQL Editor** and run `api/app/database/schema.sql`. This creates the
   tables, indexes, triggers, RLS policies and the credit RPC functions.
3. Copy **Project URL**, **anon key** and **service_role key** from
   *Project Settings → API*.
4. Frontend `web/.env.local`:
   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
   SUPABASE_SERVICE_ROLE_KEY=<service role key>   # server-only, for account deletion
   ```
5. Backend `api/.env`:
   ```dotenv
   SUPABASE_URL=https://<project>.supabase.co
   SUPABASE_JWT_SECRET=<project JWT secret>        # or rely on JWKS via SUPABASE_URL
   SUPABASE_SERVICE_ROLE_KEY=<service role key>
   STORE_BACKEND=supabase
   TRUST_PROXY_HEADERS=true                        # API is behind the BFF/proxy
   ```
   `SUPABASE_JWT_SECRET` is the legacy HS256 project secret. If omitted, the API
   verifies asymmetric tokens through the project's JWKS endpoint.
6. **Authentication → URL Configuration**:
   - Site URL: `http://localhost:3000` locally, your production URL otherwise.
   - Redirect URLs: `http://localhost:3000/auth/callback`,
     `https://<your-domain>/auth/callback`.
7. **Authentication → Providers → Google**: enable it, then paste a Google Cloud
   OAuth client id/secret. The authorized redirect URI is Supabase's callback:
   `https://<project>.supabase.co/auth/v1/callback`.
8. Email/password: enable email confirmation. Without a custom SMTP server,
   Supabase's development mailer is rate-limited and only delivers to project
   members — configure SMTP before real users sign up.

### RLS expectations (manual check once configured)

Sign in as user A in two browser profiles; A must not be able to read B's rows
using the anon key:

```sql
select * from public.jobs;  -- authenticated: only rows where user_id = auth.uid()
```

The backend connects with the service role and scopes every query by user id;
RLS is the second layer for direct client access. Cross-user API isolation is
covered by automated tests (`api/tests/test_jobs_single.py`,
`test_jobs_playlist.py`).

## 5. Razorpay Test Mode

Checkout is disabled unless all three values are set:

```dotenv
RAZORPAY_KEY_ID=rzp_test_xxxxxxxx
RAZORPAY_KEY_SECRET=xxxxxxxxxxxxxxxx
RAZORPAY_WEBHOOK_SECRET=xxxxxxxxxxxxxxxx
```

- **Amount is fixed server-side** at `PACK_PRICE_PAISE=4900` (₹49), currency INR.
  The browser cannot change it; the API ignores client-supplied amounts.
- Verify payment: server recomputes `HMAC_SHA256(order_id|payment_id, key_secret)`
  and compares in constant time before granting credits.
- Webhook: server verifies `HMAC_SHA256(raw_body, webhook_secret)`, deduplicates by
  event id, then grants entitlement only for `payment.captured` / `order.paid`.
  Grants are idempotent by payment id.
- Configure the webhook URL in the Razorpay dashboard as
  `https://<your-domain>/api/payments/webhook` and subscribe to
  `payment.captured`, `payment.failed`, `order.paid`.
- Test locally with a tunnel (for example `cloudflared tunnel --url http://localhost:3000`).

Only the ₹49 price (`PACK_PRICE_PAISE=4900`) is fixed. `FREE_CREDITS`,
`PACK_CREDITS`, `FREE_BATCH_SIZE`, `PAID_BATCH_SIZE`, `MAX_BATCH_SIZE`,
`RETENTION_DAYS` and `JOB_RETENTION_DAYS` are provisional defaults, not agreed
product terms — finalize them before launch.

## 7. Security notes

- Provider abstraction with a **demo-only** implementation; unknown provider
  names fail closed. No scraping, proxying or rate-limit circumvention exists.
- URL allowlist: only YouTube video/playlist hosts, no credentials, ports or IP
  hosts. Only ids are passed to providers — no arbitrary URL fetching.
- Backend authorization is enforced from the verified bearer token; user ids are
  never read from request bodies. Anonymous demo jobs are transient capability
  records: the unguessable job id grants access, and they expire with the
  retention window.
- Credits are atomic and idempotent; balances cannot go negative.
- RLS on every table; client roles cannot write. Credit RPCs are executable only
  by `service_role`.
- Security headers + CSP in `web/next.config.ts`; CORS allowlist and security
  headers in FastAPI.
- Secrets are server-only. `SUPABASE_SERVICE_ROLE_KEY` and Razorpay secrets must
  never be prefixed `NEXT_PUBLIC_`.

Known hardening follow-ups:

- CSP allows `'unsafe-inline'` scripts (Next.js App Router inline bootstrap).
  Moving to a nonce-based policy requires per-request nonces in middleware.
- Rate limiting is per API instance; add edge rate limits for multi-instance
  deployments.
- The in-memory store loses data on restart and is for local/demo use only;
  production startup refuses it (see §3.3).

## 9. Deployment

See [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md) for the recommended free-first
stack (Vercel + Google Cloud Run + Supabase), the full environment matrix,
verification requests, rollback and cost controls. The essential commands:

```bash
# Backend image + service (requires gcloud auth and a project id)
cd api
gcloud builds submit --tag gcr.io/<PROJECT_ID>/transcriptdock-api
gcloud run deploy transcriptdock-api --image gcr.io/<PROJECT_ID>/transcriptdock-api \
  --region asia-south1 --port 8080 --allow-unauthenticated \
  --set-env-vars APP_ENV=production,PROVIDER_NAME=demo,STORE_BACKEND=supabase,TRUST_PROXY_HEADERS=true \
  --set-secrets SUPABASE_URL=supabase-url:latest,SUPABASE_SERVICE_ROLE_KEY=supabase-service-key:latest,SUPABASE_JWT_SECRET=supabase-jwt-secret:latest,RAZORPAY_KEY_ID=razorpay-key-id:latest,RAZORPAY_KEY_SECRET=razorpay-key-secret:latest,RAZORPAY_WEBHOOK_SECRET=razorpay-webhook-secret:latest

# Frontend: import the repo on Vercel, set Root Directory to `web`,
# then set the variables from docs/DEPLOYMENT.md §3 and deploy.
```

`APP_ENV=production` requires `STORE_BACKEND=supabase`; the API refuses to start
on ephemeral storage (see §3.3).
